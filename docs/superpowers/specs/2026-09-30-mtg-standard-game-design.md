# 万智牌网页游戏（标准赛 + AI 对战）设计文档

**日期**：2026-09-30
**状态**：已获用户批准
**方案**：方案 A —— 自研 TypeScript 规则引擎 + Scryfall 数据 + 前后端分离

---

## 1. 目标与范围

在网页上实现一个可对战电脑 AI 的万智牌（Magic: The Gathering）游戏，支持**标准赛制**。

### 首版范围（可玩核心版）
- 单人 vs 电脑 AI
- 完整回合循环：抓牌、法术力、战斗、堆叠、状态检查
- 覆盖大部分标准赛常见卡：飞、践踏、连击、警戒、先攻、威吓等关键字 + 基础法术力异能 + 常见触发式异能 + 若干法术/瞬间咒语 + 基础灵气（Aura）
- 生命归零或牌库抽空判负，胜负结算 + 再来一局

### 非首版范围（后续迭代）
- 鹏洛客、Transform 牌、反色保护、不灭/辟邪等复杂隐藏信息规则
- 无法被引擎执行的卡牌文本（首版在构建池时过滤掉）

---

## 2. 技术栈

| 层 | 技术 | 职责 |
|---|---|---|
| 引擎核心（共享） | TypeScript 纯逻辑包 `@mtg/engine` | 规则引擎：回合、堆叠、优先权、战斗、状态检查、卡牌效果 |
| 后端 | Node.js + Express + WebSocket | 托管游戏会话、跑引擎、跑 AI、卡牌数据/构建 API |
| 前端 | React + Vite + TypeScript | 对战 UI、牌面渲染、操作交互 |
| 数据 | SQLite | 存储 Scryfall 下载的标准赛卡牌 |

---

## 3. 架构与数据流

```
Scryfall API ──► 数据抓取脚本 ──► SQLite({标准赛卡池})
                                      │
浏览器(React) ◄─WebSocket─► Node后端(Express)
      │                            │
      │                            ├─ 规则引擎(共享TS核心 @mtg/engine)
      │                            └─ AI 决策器
```

**单一可信来源**：所有游戏状态变更都发生在后端规则引擎里，前端只渲染和发送操作指令。保证 AI、玩家、规则一致性。

**共享引擎核心**：`@mtg/engine` 是独立纯逻辑包，无 UI 依赖，前后端共用，便于测试。

## 4. 卡牌数据建模

### 数据来源与流程
- 使用 Scryfall `bulk-data` 下载标准赛卡牌 JSON，用 `legalities.standard` 字段判定标准赛合法性。
- 抓取脚本解析 JSON 存入 SQLite。

### 能力指令模型（规则文字 → 可执行代码）
真实卡牌文本千差万别，采用「能力指令模型」——把卡牌文字拆解为结构化效果指令：

```ts
interface Card {
  id: string;
  name: string;
  manaCost: string;
  typeLine: string;          // 生物/法术/结界…
  colors: string[];
  power?: number;            // 生物
  toughness?: number;
  abilities: Ability[];      // 程序化能力列表
  oracleText: string;        // 原始文本，仅用于展示
  imageUris?: { normal: string; large: string };
}

type Ability =
  | { type: "KEYWORD"; keyword: KeywordId }                          // 飞行/践踏…
  | { type: "ACTIVATED"; cost: Cost; effect: EffectId }              // 横置：+1/+1
  | { type: "TRIGGERED"; trigger: TriggerId; effect: EffectId }      // 进场时…
  | { type: "STATIC"; effect: EffectId };                            // 静态异能
```

### 首版能力覆盖
- **支持**：飞行/践踏/连击/警觉/先攻/威吓/警戒等；基础法术力异能（横置产费）；启动式异能（横置：+1/+1）；常见触发式异能（进场/回合开始）；若干法术/瞬间咒语；基础灵气附魔。
- **不覆盖**：鹏洛客、不灭/辟邪、反色保护、Transform 牌等。卡池构建时过滤，只把能被引擎执行的卡纳入可玩列表。

### 卡牌接口解耦
- 引擎只消费 `Card.abilities[]`（结构化），与 Scryfall 原始 JSON 解耦。
- 前端展示直接用 `oracleText` + `imageUris`。

## 5. 游戏流程与规则引擎核心

引擎是**确定性状态机**，所有状态变更产出离散「事件流」，前端只渲染事件结果。

### 规则模块
```
GameEngine (状态机)
  ├─ TurnManager    回合与阶段/步骤机
  │  开始→维持→抽牌→[主阶段1]→开始战斗→宣告攻击者
  │  →宣告阻挡者→战斗伤害→结束战斗→[主阶段2]→结束→清理
  ├─ StackSystem    堆叠：咒语/异能进入堆叠，优先权轮转
  ├─ Priority       优先权：主动玩家获得优先权→传递→…
  ├─ ManaSystem     地牌横置产费、法术力池、费用结算
  ├─ CombatSystem   攻击者/阻挡者声明、伤害分配、践踏、先攻/连击
  ├─ StateBasedActions  死亡检查、0生命、灵气无对象等
  └─ EffectSystem   执行 abilities[] 指令
```

### AI 决策器
- 纯启发式（rule-based/heuristic）决策器，做到「能合理出牌、正确攻击、能结算咒语」。
- 决策点：保留地、下地上限、使用异能、攻击者选择、阻挡选择、是否施放咒语。
- 独立成 `AI` 模块，通过统一 `playAction()` 接口与引擎交互，方便后续替换更强算法。

### 对局会话（联机协议）
- 后端每局创建 `GameSession`，引擎运行在服务端。
- 玩家 → 后端：`{type:"play_land"|"cast"|"attack"|"block"|"pass"…}`
- 后端 → 玩家（WebSocket）：`{type:"game_event", events:[...]}` + 当前可操作视图
- AI 回合由后端驱动（自动 `playAction()`），玩家是无缝对局体验。

### 错误处理
非法操作（费用不足、非合法目标）在后端校验并返回明确错误，前端 toast 提示，不让非法操作进入引擎状态。

## 6. 前端 UI 与对局体验

**技术**：React + Vite + TypeScript，WebSocket 实时渲染。

### 牌桌布局
- **敌方区域（顶部）**：牌库、墓地、手牌背面（数量）、战场生物/地。
- **己方区域（底部）**：可交互生物/地。
- **中栏**：堆叠区域、回合阶段指示器、双方生命计数与手牌数。
- **操作面板**：下地、施放咒语、结束回合、传递优先权、结算/取消堆叠。

### 交互模型
- 引擎下发「当前可操作视图 + 可选动作」，前端据此渲染可点击项，非法动作禁用。
- 动作点击 → `playAction` → 后端校验执行 → 广播新状态。
- **优先级提示**：用高亮 + 文案（"你持有优先权"）清晰呈现。

### 牌面渲染
- 用 Scryfall 卡图 `imageUris` 加载，本地缓存。
- 悬停 → 大图预览（完整 oracle 文本）。
- 堆叠上的牌显示为大图。

### 首版对局闭环
1. 起始牌库（按标准赛组牌规则）+ 起手 7 张
2. 完整回合循环
3. 生命归零即分出胜负；牌库抽空判负
4. 胜负结算 + "再来一局"

## 7. 错误/边界情况设计
- 引擎非法操作拦截并返回错误（不改变状态）。
- 卡牌池构建时过滤不支持的卡（防崩溃）。
- 网络断线处理：WebSocket 重连 / 会话恢复（后续迭代明确）。
- 测试策略：引擎为纯逻辑，用单元测试覆盖回合机、堆叠、战斗、状态检查；前端用组件测试 + 手动对局验证。
