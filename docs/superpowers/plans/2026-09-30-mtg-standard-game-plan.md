# 万智牌网页游戏 实现计划

**日期**：2026-09-30
**关联设计**：`docs/superpowers/specs/2026-09-30-mtg-standard-game-design.md`
**目标**：可玩核心版 —— 单人 vs 电脑 AI，真实标准赛卡牌，完整回合循环。

> 说明：`writing-plans` 技能在当前环境不可用，本计划按设计文档手工整理为分阶段里程碑。每个里程碑可独立交付、验收，顺序执行。

---

## 里程碑总览

| # | 里程碑 | 交付物 | 验收标准 |
|---|---|---|---|
| M1 | 项目脚手架 + 共享引擎骨架 | monorepo、`@mtg/engine` 空壳、前后端骨架、CI/测试链路 | 前后端可启动，引擎可跑单测 |
| M2 | 回合与阶段机 | `TurnManager` + 阶段/步骤状态机 | 单测覆盖完整回合顺序 |
| M3 | 核心数据层（Scryfall 抓取 + 建模） | 抓取脚本、SQLite、`Card` 能力指令模型 | 标准赛卡池可写入并查询，不支持的卡被过滤 |
| M4 | 法术力 + 手牌 + 基本操作 | 下地、横置产费、施法（核心）、弃牌 | 能完成"下一代/产费/施放"的完整流程 |
| M5 | 堆叠与优先权 | `StackSystem` + `Priority` | 双方优先后结算，多人输入测试通过 |
| M6 | 战斗系统 | `CombatSystem` + 关键字（飞/践踏/先攻…） | 攻击/阻挡/伤害分配正确，含先攻与践踏 |
| M7 | 状态检查 + 胜负判定 | `StateBasedActions`、生命、牌库判负 | 死亡、0生命、抽空判负正确 |
| M8 | AI 玩家 | 启发式决策器 | AI 能出牌、攻击、阻挡、结算 |
| M9 | 后端对局会话 + WebSocket | `GameSession`、游戏事件协议 | 玩家 ↔ 后端实时同步 |
| M10 | 前端对战 UI | React 牌桌、操作面板、卡图渲染 | 完整单局可玩性验证 |
| M11 | 端到端联调 + 验收 | 单局完整对局 | 打导入一局完整对局、胜负结算、"再来一局" |

## 依赖关系

```
M1
 └─ M2 → M4 → M5 ─┬─→ M6 → M7 ─→ M8 ─→ M9 ─→ M10 ─→ M11
      └── M3 ─────┘
```

- M2/M3 相对独立，可并行起始。
- M4 依赖 M2（回合机）+ M3（卡牌数据）。
- 战斗（M6）依赖堆叠/优先权（M5）与状态检查（M7 部分）。
- AI（M8）依赖完整规则（M7）；后端会话（M9）依赖前序全部；前端（M10）依赖 M9。

## 各里程碑任务

### M1 项目脚手架 + 共享引擎骨架
- 用 pnpm workspaces 建 monorepo：`packages/engine`、`apps/server`、`apps/web`。
- `@mtg/engine`：纯 TS 包，无 UI 依赖；暴露 `GameEngine` 空壳与类型定义。
- 后端 Node + Express + WebSocket（`ws`），前端 React + Vite + TS。
- Vitest 测试 + `eslint`、`tsc` 检查链路。
- 提交可运行的骨架（前后端 hello 连通）。

### M2 回合与阶段机
- `TurnManager`：回合/阶段/步骤枚举与转换（开始→维持→抽牌→主1→开始战斗→宣告攻击→宣告阻挡→伤害→结束战斗→主2→结束→清理）。
- 持有当前 `turn`、`phase`、`activePlayer`。
- 单测：完整回合顺序推进、阶段切换。

### M3 核心数据层
- 抓取脚本：调 Scryfall `bulk-data`（default-cards）+ `legalities.standard` 过滤。
- 解析为 `Card` 的 `abilities[]`（能力指令模型）；不支持的类型/卡标记 `supported=false` 并过滤。
- 实现能力解析器：关键字列表、法力费用解析、基本启动/触发/静态异能识别。
- SQLite 存取：卡表、能力表、卡池构建接口。
- **首版能力覆盖**：飞/践踏/连击/警觉/先攻/威吓/警戒；横置产费；`横置:+1/+1` 类；进场/回合开始触发；若干法术/瞬间；基础灵气。

### M4 法术力 + 手牌 + 基本操作
- `ManaSystem`：地横置产费、法术力池、重置阶段重置。
- `PlayerState`：牌库/手牌/战场/墓地/生命/地。
- 基本动作：`play_land`、`activate_mana`、`cast`（费用校验/支付）、`pass`。
- 引擎对非法操作返回明确错误（不改变状态）。

### M5 堆叠与优先权
- `StackSystem`：咒语/异能入堆叠、结算、消散。
- `Priority`：主动玩家优先权 → 传递 → 让过后推进；每步玩家可介入。
- 支持「全员让过 → 结算堆叠顶」「堆叠空且全员让过 → 进入下一阶段」。
- 单测：堆叠顺序、优先权轮转、结算流程。

### M6 战斗系统
- `CombatSystem`：宣告攻击（横置、合法性）、宣告阻挡、伤害分配顺序。
- 关键字：先攻/连击（首个伤害步骤）、践踏（过量穿透）、飞行（空档/阻挡约束）、威吓、警戒（不需要横置攻击）。
- 战斗伤害结算 → 触发后续状态检查。
- 单测：各类关键字组合进攻/阻挡场景。

### M7 状态检查 + 胜负判定
- `StateBasedActions`：致命伤害死亡、0或以下生命、灵气无对象、N个地传奇检查等首版所需项。
- 胜负：生命≤0 判负、牌库抽空判负。
- 判负时机与结算顺序正确。

### M8 AI 玩家
- 启发式决策器：评估手牌/战场，决定下地、保留费、施法、使用异能、攻击者选择、阻挡选择。
- 通过统一 `playAction()` 接入引擎，支持"自动走完自身回合"。
- 验证：AI 对简单牌组能持续打完整局不卡死。

### M9 后端对局会话 + WebSocket
- `GameSession`：加载卡池、双方起手、驱动引擎、管理回合轮转。
- 协议：`playAction`（入）/`game_event` + 可操作视图（出）。
- 每事件广播增量事件流；非法操作返回错误。
- 支持 AI 作为对手时自动响应。

### M10 前端对战 UI
- React 牌桌：敌方区/己方区/中栏（堆叠+阶段指示器+生命）、操作面板。
- 每节点点击 → `playAction`；合法动作可点、非法禁用。
- 卡图渲染（Scryfall `imageUris`）+ 悬停大图 + 堆叠大图。
- 优先级/阶段/我方可操作提示（"你持有优先权"）。

### M11 端到端联调 + 验收
- 完整单局闭环：起手→多回合→胜负→"再来一局"。
- 手动验收清单（见设计文档第 6 节）。
- 修复联调问题，跑通全部单测。

## 风险与应对
- **规则引擎工程量庞大**：按里程碑小步交付，每个里程碑可独立验收；先在 M6/M7 收敛核心规则。
- **卡牌能力建模无法穷尽**：能力指令模型 + 构建池过滤，只纳入引擎可执行的卡。
- **AI 决策质量**：首版用启发式，保证"能打完整局"，不强求最优。
- **Scryfall 数据量大**：抓取脚本按需过滤标准赛字段，体积可控。

## 测试策略
- 引擎 M2–M7 以 Vitest 单测为主，覆盖状态机边界与规则细节。
- M8 AI 用无头单测验证对局不崩溃。
- M9/M10 端到端手动对局验证 [+ 可选 Playwright]。
